# 数据规范（Data Schema）

> 这份文档定义 travel-planner 的**参考数据怎么组织、怎么加、加完怎么验**。
> 目标：以后持续加城市/景点/美食时，**只改数据文件，不改脚本**，并且**数据必须可追溯**。
>
> 规范版本：1.0 ｜ 最后更新：2026-11-09

---

## 0. 三条铁律

| # | 规则 | 为什么 |
|---|------|--------|
| 1 | **不编造**。拿不准的价格/时长写 `待核实`，不要写「约XX」 | 估算值会被当成事实转述给用户，比没有数据更糟 |
| 2 | **有出处**。每条数据要么在 `references/travel_data.json` 登记来源，要么在表里标注 | 三个月后没人记得「约60」是哪来的 |
| 3 | **单一事实源**。同一份数据只存在于一处 | md 与代码内置库双份 = 必然漂移 |

## 1. 数据文件全景

| 文件 | 格式 | 解析者 | 内容 |
|------|------|--------|------|
| `references/cities_attractions.md` | Markdown 表格 | `generate_plan.py` | 景点库（按城市分章） |
| `references/food_guide.md` | Markdown | `generate_plan.py` | 美食手册（按城市分章） |
| `references/travel_data.json` | JSON | `generate_plan.py` / `transit.py` | **城市注册表**：别名、地铁覆盖、来源、核实状态、风格类别词表、地铁扫描优先级 |
| `references/image_index.json` | JSON | `generate_plan.py` / `validate_data.py` | **图片索引**：城市 → 景点 → 图片直链 + 原始页面 + 来源站点 |
| `references/images/` | 目录 | `fetch_images.py` | 图片本地缓存（默认不入 git） |
| `references/weather_cities.json` | JSON | `weather_query.py` | 天气城市码（3137 个） |
| `references/station_cache.json` | JSON | `train_store.py` | 12306 车站电报码（3407 站） |
| `references/districts.json` | JSON | `bus_query.py` | 区县 → 地级市映射 |
| `references/mygolbs_cities.json` / `bus_cities.json` | JSON | `bus_query.py` | 公交数据源覆盖城市 |

**校验**：`python3 scripts/validate_data.py`（见 §6）。

## 2. 景点数据格式（`cities_attractions.md`）

### 2.1 章节结构

```markdown
## 八、丹东（鸭绿江流域·中朝边境）

> 定位：一句话说明这座城市玩什么。最佳季节：…。
> 部分票价参考网络公开信息，以预订平台实际显示为准。

| 景点 | 门票(元) | 游玩时长 | 区域 | 类别 | 省钱等级 | 必去指数 | 开放时间 | 小红书/博客核心评价 |
|------|---------|---------|------|------|---------|---------|---------|---------------------|
| 鸭绿江断桥 | 30 | 1h | 丹东市振兴区 | 历史/红色 | 💰 | ★★★★★ | 8:00-17:00 | 抗美援朝历史见证，桥体弹痕累累 |

**丹东必吃：** 朝鲜族冷面、黄蚬子炒馇子…
> 详细价格见 `references/food_guide.md`

**丹东省钱黄金路线：**
- 纯免费路线：…

**丹东游玩小贴士：**
- 🚗 交通：…
```

**规则**：
- 章节标题必须是 `## <中文数字>、<城市名>（<省份/定位>）`；
- 城市名 2-4 个汉字（`travel_data.json` 里注册同名 key）；
- 序号连续递增（`一、二、三…`），末尾是「跨城市联游建议」；
- 标题后建议写一行 `>` 定位说明；票价有波动风险的加一句「以预订平台实际显示为准」。

### 2.2 列定义（9 列，顺序固定）

| 列 | 名称 | 写法 | 解析结果 |
|----|------|------|----------|
| 1 | 景点 | 景区官方名 | `name` |
| 2 | 门票(元) | 见 §2.3 | `ticket_price`（float 或 **None=未知**） |
| 3 | 游玩时长 | `1h` / `2-3h` / `半天` / `半天-1天` / `1-2天` / `全天` | `avg_duration_h` |
| 4 | 区域 | 行政区名，如 `郴州市北湖区` | `district` |
| 5 | 类别 | `主类/子类`，如 `自然/湖泊` | `category` |
| 6 | 省钱等级 | `⭐`免费/低价 ｜ `💰`需预算 ｜ `💰💰`高消费 | `saving` |
| 7 | 必去指数 | `★★★★★` ~ `★☆☆☆☆` | `rating`(1-5) / `priority` |
| 8 | 开放时间 | `全天` / `9:00-17:00` / `9:00-16:30（周一闭馆）` | 文本 |
| 9 | 小红书/博客核心评价 | 一句话亮点 + 避坑提示 | `tips` |
| 10 | 图片（可选） | `![景点名](图片URL)` | `image`（空串=无图） |

> 「图片」列是**可选**的：9 列的表也合法。没有配图的景点不影响其它数据。

### 2.3 门票列写法（**关键**）

| 写法 | 含义 | 解析值 |
|------|------|--------|
| `免费` | 确认免费 | `0.0` |
| `30` | 确认票价 30 元 | `30.0` |
| `40（学生20）` | 主价 40，括号内是优惠 | `40.0` |
| `96-120` | 区间，取下限 | `96.0` |
| `80（网购约65）` | 主价 80，括号内是渠道价 | `80.0` |
| `免费（小火车20）` | 景点免费，括号内是附加项目 | `0.0` |
| **`待核实`** | **价格未确认 —— 不要猜** | `None`（未知） |

> ⚠️ **`待核实` 的含义是「未知」，不是「免费」。**
> 生成行程时会显示「票价待核实」，预算估算会跳过该项，**不会**编一个数字出来。
> 拿到真实价格后，把 `待核实` 换成具体数字即可。

### 2.4 类别词表

主类建议只用这几个（`travel_data.json` → `style_categories` 里定义了对应的子标签）：

`文化` `自然` `美食` `购物` `亲子` `夜景` `历史` `艺术` `网红打卡`

子类自由发挥（`溶洞/奇观`、`自然/湖泊`、`民族文化`…），**匹配时按「主类 + 子类」双匹配**，
所以 `自然/湖泊` 会被「自然」风格命中。

新增子标签时，把关键词补进 `travel_data.json` 的 `style_categories` 对应列表即可。

## 3. 实景图片（`images/` + `references/image_index.json`）

景点除了文字，还得能「看见」。图片**随仓库提交**，用 GitHub raw 链接稳定展示，
不依赖原始网站的临时链接。

| 文件 | 内容 | 进 git |
|------|------|--------|
| `references/image_index.json` | 图片索引：城市 → 景点 → `{url, page, title, source, query, local, raw_url}` | ✅ |
| `images/<城市>/<景点>.jpg` | 实景图二进制 | ✅ 随仓库提交（图库模式），raw 链接直接可用 |

### 3.1 索引字段

| 字段 | 说明 |
|------|------|
| `url` | 图片原始直链（来源站点的图，可能防盗链/过期） |
| `raw_url` | **GitHub raw 链接**（`https://raw.githubusercontent.com/<owner>/<repo>/<branch>/images/...`） |
| `page` | **原始页面 URL** —— 溯源用，这张图出自哪个站点的哪篇内容 |
| `title` | 原站标题 |
| `source` | 来源站点（百度百科 / 携程 / 去哪儿 / 人民网 / 新浪…） |
| `query` | 检索时用的关键词（便于人工复核） |
| `local` | 图片在仓库里的相对路径（`images/...`） |

### 3.2 加图 + 发布到 GitHub

```bash
# 1) 检索并写入索引（只写原始链接）
python3 scripts/fetch_images.py index --city 郴州
# 2) 看「该放哪些图、放哪」的清单（手动补图时照着放）
python3 scripts/fetch_images.py manifest --city 郴州
#    或者让脚本自动下载到 images/<城市>/
python3 scripts/fetch_images.py download --limit 999
# 3) 把 md 图片列换成 GitHub raw 链接（不加代理）
python3 scripts/fetch_images.py github-url
#    不要代理时： --proxy ""
#    指定仓库时： --repo yao1987825/travel-planner --branch main
# 4) 提交图片与索引（图片二进制随仓库入库）
git add references/image_index.json references/cities_attractions.md
git commit -m "data(images): 更新景点实景图索引"
git push
```

> 图片文件名规则：`images/<城市>/<景点名>.jpg`，景点名里的特殊字符替换成 `_`
> （`东江湖（雾漫小东江）` → `东江湖_雾漫小东江_.jpg`）。
> `manifest` 命令会把清单和每个缺失项的**原站直链 + 原始页面**都列出来。

### 3.3 展示链路

```
GitHub raw 直链（默认，不加代理）：
    https://raw.githubusercontent.com/yao1987825/travel-planner/main/images/丹东/鸭绿江断桥.jpg

个别网络环境 raw 不稳定时，可用 --proxy 生成带代理前缀的链接
（如 https://gh-proxy.com/...），但代理中转不稳定，不推荐默认使用。
```

### 3.4 图片规则

- **必须是该景点的真实照片**，不许用风格相近的风景图充数；
- 检索按「城市 + 景点名」，并设**硬门槛**：标题/页面里必须出现景点名本身
  （去括号后的核心名，或其前 3 个字）—— 只匹配到城市名不算数
  （否则「阳山秤架干坑古树群」会被配到「阳山某公园」的新闻图）；
- 菜谱/游戏/房价等无关结果直接排除；
- 找不到就**留空**，不硬凑（`大唐演义` 就是没配到图，如实留空）；
- **必须记 `page`（原始页面）**，图片版权属原作者/站点，索引只做检索与溯源；
- 原始链接若防盗链/过期，以 `raw_url`（GitHub raw）为准。

## 4. 美食数据格式（`food_guide.md`）

结构与景点库一致，按城市分章：

```markdown
## 六、丹东美食

### 核心特色：朝鲜族冷面 + 黄蚬子炒馇子 + 鸭绿江鲤鱼

#### 朝鲜族冷面
> 一句话说明风味特点。

| 项目 | 详情 |
|------|------|
| 省钱档 | … |
| 普通档 | … |

**推荐店铺：**
- …

**丹东必吃：** …      ← 这行会被 generate_plan 用作晚餐提示
```

**必须包含的一行**：`**<城市名>必吃：** …`
`generate_plan.py` 会把它解析成该城市的晚餐提示；若写成
`**<城市名>早餐：** …` / `**午餐：**` / `**晚餐：**`，则分别对应三餐（可选）。

## 5. 城市注册表（`references/travel_data.json`）

```json
{
  "丹东": {
    "aliases": ["丹东市", "鸭绿江", "鸭绿江流域", "中朝边境"],
    "metro": false,
    "province": "辽宁",
    "attractions_source": "用户提供素材（断桥票价以预订平台实时显示为准）",
    "food_source": "用户提供素材 + 项目美食手册",
    "verified": "2026"
  }
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `aliases` | 否 | 用户口语/别称，命中后按该城市查。**别名与其它城市的别名不得重复** |
| `metro` | 是 | 该城市是否有地铁（影响行程里的交通文案） |
| `province` | 否 | 省份 |
| `attractions_source` | **是** | 景点数据出处（谁/哪个平台/哪一年） |
| `food_source` | **是** | 美食数据出处 |
| `verified` | **是** | 数据核实年份，如 `2025` |

注册表里还有两块全局配置（新增城市时一般不用动）：

| 键 | 说明 |
|----|------|
| `style_categories` | 风格 → 类别关键词表。匹配用**双向子串**（`历史/文化` 里的「文化」能命中「文化」风格，「名山」里的「山」能命中「自然」） |
| `metro_priority_cities` | 地铁「地标→城市」反查时的扫描优先级（常用城市排前面，避免联网遍历 55 城） |

> `aliases` 里出现「鸭绿江」这种**区域/流域**名时，说明该城市是区域行程的落点，
> 景点应覆盖整个区域在行程上的主要落点。

## 6. 新增一个城市的完整流程

1. **建数据**：在 `cities_attractions.md` 末尾（跨城市联游建议之前）加一节，
   按 §2.1 写表格，按 §2.3 写门票；
2. **写美食**（可选但建议）：在 `food_guide.md` 加一节，至少写 `**<城市名>必吃：**` 一行；
3. **注册**：在 `travel_data.json` 的 `cities` 里加一条（**必须**填 `attractions_source` /
   `food_source` / `verified`）；
4. **配图**：`python3 scripts/fetch_images.py index --city <城市>` 然后
   `python3 scripts/fetch_images.py sync`（图片列见 §3）；
5. **校验**：`python3 scripts/validate_data.py` —— 必须 0 error；
6. **测试**：`python3 tests/test_journey.py --offline` —— 加一条该城市的断言；
7. **提交**：commit message 里写清数据来源。

## 7. 校验脚本

```bash
python3 scripts/validate_data.py                # 全量校验
python3 scripts/validate_data.py --city 丹东    # 只查某个城市
```

检查项：

| 级别 | 检查内容 |
|------|----------|
| ❌ error | 章节序号不连续、表格列数不对、门票列写法非法、重复景点名、城市未在注册表登记、注册表缺来源字段、别名冲突、必去指数格式错 |
| ⚠️ warn | 门票写 `待核实`、没有「必吃」行、时长/开放时间为空、类别主类不在词表里 |

退出码：0 = 无 error；1 = 有 error。

## 8. 真实数据准则

### 7.1 价格

- **优先用官方/权威源**：景区官网、政府文旅公示、票务平台实时价；
- **注明时效**：写「2026-11 核价」或在 `verified` 字段记年份；
- **波动大的加提示**：断桥/游船/演出这类写「价格实时变动，以预订平台实际显示为准」；
- **拿不准就写 `待核实`**——`待核实` 会被如实告诉用户，不会变成假数字。

### 7.2 评价文案

- 写「亮点 + 避坑」，别写营销词；
- 有避坑信息的要点出来（如「村民带路『免费景点』实为购物点，勿踩坑」）。

### 7.3 禁止事项

- ❌ 凭印象写价格（「约XX」这种没出处的估算）；
- ❌ 把「未知」写成「免费」；
- ❌ 在代码里内置一份景点数据（会导致与 md 双源漂移）——所有城市数据只在 md 里。
